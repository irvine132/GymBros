# HTTPS public de test Gym Bro — état bloqué avant publication

Ce changement est réservé à l'API de test. URL prévue (PAS encore active) : `https://hermes-dev-hub.taildf8f08.ts.net/gym-bro/api/v1`. L'API origin reste sur `127.0.0.1:18081`; le gateway Python `scripts/public_api_gateway.py` écoute seulement `127.0.0.1:18083`. Il autorise uniquement les méthodes/routes nécessaires à Slice A, contrôle la taille des requêtes et réponses, refuse les autres chemins et réduit les en-têtes transmis à Authorization/JSON. Les écritures sont limitées globalement à 30/min pour auth et 120/min pour le reste (limite partagée entre testeurs, non garantie contre abus distribué). Aucune route admin, DB, preview ou autre service ne doit être exposée.

Sauvegarde effective avant tentative : `.local/funnel-before-gym-bro.json` (hors Git). La tentative additive était :

    tailscale funnel --bg --yes --https=443 --set-path=/gym-bro http://127.0.0.1:18083

Elle a retourné `Access denied: serve config denied`. Aucun changement de configuration Funnel : lecture après tentative `.local/funnel-after-gym-bro.json`, comparaison des autres handlers 443, des autres Web, TCP et AllowFunnel : tous identiques ; `/gym-bro` absent. Il est explicitement interdit de faire `sudo`, de changer l'opérateur, de remplacer `/` ou les listeners existants. Un opérateur disposant déjà des droits légitimes doit décider de l'ajout de cette seule route ; la configuration et la vérification TLS publique restent à faire. Ne pas interpréter le smoke local 401 comme une preuve Internet. Après Go administratif, vérifier la config effective, le DNS public et `curl --resolve` par l'IPv6 publique, puis les parcours authentifiés et les refus d'accès privé/IDOR sans journaliser jetons ni mots de passe.

Le client Flutter a un délai de requête et un message d'erreur réseau avec action Réessayer lors de la restauration de session ; la session n'est plus effacée lors d'une panne transitoire. Ce changement est vérifié par tests locaux mais n'est **pas** présent dans l'APK historique 2001. Aucun APK 2002 n'est compilé ou livré tant que la route publique n'est pas réellement vérifiée ; le binaire 2001 continue de pointer sur le loopback et nécessite adb reverse. La limitation de l'espace disque (~765 Mo avant nouveau build) impose aussi une vérification de marge avant compilation. Aucun lancement Android sur appareil n'a été constaté.
