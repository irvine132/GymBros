# ADR-003 — Privacité des profils et fil Abonnements (Slice B)

Les comptes existants restent publics par défaut. Le pseudo est immuable dans ce lot ; nom public facultatif et unité préférée modifiables par le propriétaire. Un profil privé reste trouvable par pseudo/nom (identité minimale et état de demande uniquement) afin de permettre une demande de suivi, mais ses publications, y compris celles historiquement marquées PUBLIC, sont invisibles aux tiers non acceptés. Blocage dans les deux sens masque profil, recherche, détail, fils et interactions ; le propriétaire conserve son historique. Les demandes PENDING ne donnent jamais accès. Le suivi public est ACCEPTED immédiatement ; le suivi privé requiert acceptation par le destinataire seulement, refus retire la demande. Un unfollow retire la relation, une nouvelle demande est possible.

La migration V3 Google déjà enregistrée dans la base de test précède V4 mais sa source n'était pas dans le worktree produit. Pour conserver la validation Flyway sans `repair`, contournement de checksum ni altération de données, seule la migration V3 historique est copiée à l'octet près depuis le worktree WIP préservé ; ni code OAuth, ni configuration fournisseur, ni outillage Android WIP ne sont importés. Le login par mot de passe répond 401 pour une identité sans hash. La nouvelle migration V4 est additive et ne modifie pas les identités existantes ; une revue indépendante doit contrôler ce point de jonction avant diffusion.

PUBLIC est visible dans Découvrir seulement si auteur public, non bloqué. Dans Abonnements, les relations ACCEPTED permettent PUBLIC et FOLLOWERS ; un post FOLLOWERS est invisible via Découvrir et visible au détail uniquement des abonnés acceptés ou de l'auteur. La publication reste explicitement déclenchée depuis une séance terminée : défaut PUBLIC historique, choix FOLLOWERS uniquement si l'API et l'interface le proposent ensemble. Aucun brouillon ni séance privée n'est exposé par ces projections. Tri par `(published_at DESC, id DESC)` avec curseur opaque de ce couple ; filtrer les droits avant LIMIT et émettre le curseur de la dernière ligne affichée. Chaque requête revérifie les relations et blocages ; une page déjà affichée est rafraîchie après les mutations de l'interface. Aucun effacement ni backfill destructif.
