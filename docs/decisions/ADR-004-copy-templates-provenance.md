# ADR-004 — Copie, snapshot et provenance (tranche C)

Une copie se fait depuis un post lisible **au moment de l'action** selon exactement le prédicat du détail (audience, compte privé, suivi accepté, blocage bilatéral, retrait). La copie crée un template appartenant à l'acteur ; une paire (owner, source post) est unique pour rendre le retry idempotent. Le snapshot `definition_version=1` ne contient que titre, exercices et séries (répétitions/charge/unité comme *cibles ajustables*, pas les résultats accomplis par le copieur), jamais email, dates, records, UUID de séance d'autrui ou JSON de session brut. Le propriétaire peut modifier son template, la source et les copies d'autres comptes ne changent pas. Démarrer crée un brouillon indépendant via `clientId` idempotent dans le moteur existant, avec provenance source du template. La fin de séance reste privée et la publication distincte et volontaire.

La copie reste utilisable après révocation d'accès à la source : le snapshot local déjà acquis n'est pas effacé. En revanche, tous les endpoints qui exposent une attribution (template, séance propriétaire, post publié par le copieur) ne donnent l'identité et l'ID source que si le lecteur pourrait lire **maintenant** le post source. Sinon ils renvoient seulement `sourceUnavailable: true`, sans titre, auteur, ID ni contenu source. Le post source retiré/masqué n'est jamais réouvert par une provenance. Une référence interne en base n'est pas un droit d'accès. La lecture et mutation du template et du brouillon restent strictement owner-scoped. Pas de suppression de données ni migration de contenu historique ; V5 est additive. Aucun droit ou visibilité supplémentaire n'est créé par la copie.
